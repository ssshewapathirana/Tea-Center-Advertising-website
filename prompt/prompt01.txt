# FULL MASTER PROMPT

## NEWBERG TEA CENTRE — PRODUCTION-READY FULL-STACK WEB APPLICATION

You are a senior software architect, senior Next.js engineer, React engineer, PostgreSQL/Neon database engineer, UI/UX designer, security engineer, DevOps engineer and QA engineer.

Your task is to build the complete **Newberg Tea Centre** full-stack web application.

This is not a tutorial project.

This must be structured as a real production-oriented application that can be deployed to Vercel and use Neon PostgreSQL as its persistent database.

The user will provide the Neon PostgreSQL connection string through an environment variable.

The supplied Newberg Tea Centre HTML demo is the PRIMARY visual and interaction reference.

DO NOT replace the design with a generic SaaS dashboard.

DO NOT redesign the public website unnecessarily.

DO NOT remove existing useful functionality.

The reference demo must be carefully studied before implementation.

============================================================

1. PRODUCT PURPOSE
   ============================================================

Newberg Tea Centre is a tea information and transparent pricing platform.

The public website allows visitors to:

* discover tea categories
* browse tea grades
* understand grade descriptions
* see current tea prices
* see price changes
* see availability
* explore the tea production journey
* understand tea benefits
* calculate price by gram quantity
* compare tea grades
* discover Ceylon tea

The administration system allows authorized staff to:

* manage tea categories
* create/edit/delete tea grades
* update prices
* preserve complete price history
* update availability
* mark teas as available
* mark teas as low stock
* mark teas as out of stock
* publish/unpublish teas
* manage category information
* perform bulk price updates
* inspect price history
* inspect admin activity
* manage public-facing information
* manage application settings

The central business feature is:

ADMIN CHANGES TEA PRICE
↓
DATABASE
↓
PRICE HISTORY CREATED
↓
PUBLIC WEBSITE REFRESHED
↓
CUSTOMER SEES CURRENT PRICE + CHANGE

The application must make this workflow reliable.

15. PRICE CHANGE CALCULATION
============================

Formula:

percentageChange =
((newPrice - oldPrice) / oldPrice) × 100

Example:

Old:
1280

New:
1310

Change:
+2.34%

Handle:

old price = null
old price = 0
new price = 0
negative prices
invalid numeric input

safely.

Display:

↑ 2.34%

or:

↓ 2.34%

or:

No change

Use appropriate semantic states.

17. PRICE UPDATE TRANSACTION
============================

When an administrator changes a price:

1. authenticate user
2. authorize permission
3. validate input
4. read current price
5. calculate difference
6. create price history record
7. close previous price record
8. create new current price
9. create activity log
10. revalidate public data
11. return success

Use a PostgreSQL transaction.

If any step fails, rollback the entire operation.

Do not leave partial updates.
